# 寵物小精靈四人私人房伺服器

## 本機

使用 Node.js 22 或更新版本，執行 `npm ci`、`npm start`。預設 WebSocket 為 `ws://127.0.0.1:2567`，健康檢查為 `/health`。遊戲前端開啟 `/online.html`；單機版 `/index.html` 獨立保留。

## Render 免費部署

此目錄是獨立後端專案，可放入獨立 Git repository。建立 Render Web Service：Node runtime、`npm ci`、`npm start`、health path `/health`，instance 選 **Free**。`render.yaml` 也明確指定 `plan: free`。不要啟用付費 instance、Redis、資料庫或額外服務。

部署成功後，將前端 `online-config.js` 的正式環境網址設為該服務的 `wss://...onrender.com`，再發布前端。不要在正式網站填入 localhost，也不要把登入憑證放進前端。

## 規則與功能

- 最多四名真人；房主開始後空位由 AI 補上，禁止新玩家中途加入，既有玩家仍可重連。
- 房間碼為 10 個英數字元；房間不列入公開房間清單。
- 暱稱及角色選擇；各自獨立金幣、棋子及商店，別人的商店不傳送。
- 伺服器驗證買棋、刷新、人口、出售、棋子擁有權、部署區域及人口上限。
- 準備時間 60 秒；全部存活真人準備好可提早開戰；四個場地同步結算。
- 30 Hz 移動、5 Hz 狀態快照（只傳送正在查看的戰鬥棋盤，WebSocket 啟用壓縮）、0.7 秒戰鬥節拍。技能事件有序號，前端去重播放。
- 斷線預留 60 秒；重連保留席位及狀態，逾時或主動離開後 AI 接管。

## 原型限制

- 目前房間只保存在伺服器記憶體。服務重啟、重新部署或免費主機休眠導致程序重建時，既有對局不能恢復；不是跨重啟永久存檔。
- 不包含帳戶、排名、公眾配對。房間碼持有者可在開戰前加入。
- 免費主機有資源及月用量限制，部署設定不代表無限用量承諾。

## 驗證

`npm test` 使用獨立測試程序及真實 WebSocket 客戶端，檢查不同席位、商店隱藏、房主限制、AI 補位、擁有權驗證、扣款、同步戰鬥、相同結算及斷線恢復。

修改單機規則後，需以 `work/prepare-multiplayer.cjs` 同步 `rules/`，再重新測試。瀏覽器 SDK 與伺服器使用相容的 Colyseus 0.17 系列；保留 SDK MIT 版權聲明。
